## findings
- severity: S2
  dimension: correctness
  issue: The process-wide in-flight counter is not atomic across event loops.
  evidence:  sugra_api_mcp/server.py:134-156 checks, increments, and decrements _in_flight_tool_calls without a lock; concurrent event loops in different threads can both pass the check or lose decrements, violating the process-wide cap and drifting the counter.
  required_fix: Protect admission and decrement with a module-level threading.Lock, or explicitly enforce a single event loop for every server instance.
- severity: S2
  dimension: security
  issue: The shared caps provide no fairness and leave a cheap single-caller denial of service.
  evidence:  sugra_api_mcp/server.py:134-156 applies one shared 32-call budget, while sugra_api_mcp/tools/gateway.py:20-81 allows 8 searches plus up to 24 callers waiting for search capacity without any principal identity; a single caller can continuously occupy all slots and make legitimate calls receive server_busy.
  required_fix: Add per-principal concurrency or rate admission, reserve capacity for other principals, or use a fair scheduler before relying on the process-wide caps.
- severity: S3
  dimension: business-logic-vs-spec
  issue: The public error documentation does not describe the actual query bound.
  evidence:  README.md:398-399 describes the limit as 64 words, but sugra_api_mcp/catalog/search.py:425-443 counts every _tokens result of at least two characters, including repeats and excluding shorter tokens.
  required_fix: Document the exact tokenization rule consistently in README.md and user-facing hints.
- severity: S3
  dimension: maintainability
  issue: The alias-equivalence test is not exhaustive against the old implementation.
  evidence:  tests/test_search_bounds.py:109-126 computes the exhaustive alias expectation independently from normalized tokens and only calls the old _alias_matches reference for one endpoint and its first 50 expansions, so regressions for other endpoint and alias pairs can pass.
  required_fix: Compare _alias_matches(_endpoint_text(endpoint), expansion) with _alias_matches_profile for every endpoint and every alias expansion, or use a frozen pre-change oracle.
- severity: S3
  dimension: maintainability
  issue: Timing-based tests can be false positives or flaky on slow or heavily loaded CI.
  evidence:  tests/test_search_bounds.py:339-344 cancels the in-flight-cap test after a fixed asyncio.sleep(0.05) without synchronizing on entry, so it may cancel before admission and fail to test cleanup after an admitted cancellation; tests/test_search_bounds.py:218-224 also requires elapsed_ms >= 100 after a 0.1 second wait with integer truncation.
  required_fix: Signal deterministic entry before cancellation and assert eventual counter cleanup; replace the exact elapsed_ms threshold with a tolerance or a state-based assertion.

## summary
The long-query event-loop stall and the documented queued-cancellation behavior are addressed, but the unsynchronized process-wide counter and principal-free shared admission leave S2 correctness and denial-of-service gaps.
