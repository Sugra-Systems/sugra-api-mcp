## findings
- severity: S2
  dimension: business-logic-vs-spec
  issue: Queued cancellation violates the stated requirement that a cancelled search remains counted until worker completion.
  evidence:  sugra_api_mcp/tools/gateway.py:47-50: asyncio.wrap_future propagates caller cancellation to the underlying concurrent future, so a queued search cancelled before the worker starts is cancelled and its done callback releases the slot before the worker finishes it.
  required_fix: Shield the wrapped future from caller cancellation, or explicitly revise the invariant and add coverage for cancellation before and after worker start.
- severity: S2
  dimension: resource-efficiency
  issue: Multiple FastMCP instances in one process can collectively exceed the claimed 32-call process limit.
  evidence:  sugra_api_mcp/server.py:137-158: _in_flight_tool_calls is declared on the class but incremented through self, creating an independent instance counter for each SugraFastMCP object.
  required_fix: Use one process-level limiter and counter shared by every server instance, or enforce and test a singleton server invariant.
- severity: S2
  dimension: security
  issue: A caller can continuously occupy the global search queue and cheaply force legitimate catalog searches to receive server_busy.
  evidence:  sugra_api_mcp/tools/gateway.py:22-31,169-205: one global eight-entry search budget immediately returns server_busy with no per-caller quota, fairness, or reserved capacity; tests/test_search_bounds.py:1-8 identifies catalog search as reachable without an upstream call.
  required_fix: Add authentication or per-principal admission control and fair scheduling, or reserve search capacity for independent callers.
- severity: S3
  dimension: maintainability
  issue: Running the SDK under AnyIO's Trio backend cannot await the asyncio-wrapped executor future.
  evidence:  sugra_api_mcp/tools/gateway.py:2-6,47-50: the implementation is tied to asyncio.Future; tests/test_search_bounds.py:27-31 forces only the asyncio AnyIO backend.
  required_fix: Use an AnyIO-native worker and capacity limiter, or explicitly reject unsupported backends and test the supported runtime contract.
- severity: S3
  dimension: maintainability
  issue: The tests can miss ranking regressions and cancellation paths while their timing checks are likely to flake on loaded CI.
  evidence:  tests/test_search_bounds.py:96-124 compares profiles to the same tokenizer and samples aliases every 40th endpoint instead of comparing cached scoring with the old implementation; tests/test_search_bounds.py:61-71 uses a 0.1 second threshold and tests/test_search_bounds.py:147-148 uses a 0.2 second event-loop gap threshold.
  required_fix: Add a pre-change scoring reference over all endpoints, fields, aliases, and parameters, add queued-cancellation and exception-release tests, and replace tight timing assertions with deterministic synchronization or generous CI-safe bounds.
- severity: S3
  dimension: business-logic-vs-spec

  evidence:  sugra_api_mcp/server.py:142-153 returns the in-flight refusal directly, while sugra_api_mcp/errors.py:37-50 creates a payload without elapsed_ms; README.md:401 states that all error payloads carry elapsed_ms.
  required_fix: Pass refusal results through the common error envelope or add elapsed_ms explicitly to every new refusal payload, including CLI output.
