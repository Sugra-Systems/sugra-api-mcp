## summary
Membership scoring from cached frozensets matches the old per-field tokenization, alias phrases use the same joined-token haystack, and frozen Endpoint objects plus an identity check on the cached pair block stale id reuse. Tools and the CLI refuse oversized queries with query_too_long before scoring, search_catalog raises if they do not, and a 64-token / 1000-character bound is well above realistic agent queries while cutting off the 20k-character stall. Search runs on one worker with a locked pending counter released from the future done-callback (including cancel-after-start and worker exceptions); fetch_data calls call_endpoint the function so the in-flight cap does not nest; wrap_future is sound on the asyncio loop used by stdio, uvicorn, and the anyio tests. A made-up sugra_ bearer can still occupy the eight search slots and get server_busy for other searchers, which is the intended refuse-not-queue trade and no longer stalls the process. Refusal spans attach only allowlisted name, success, code, and duration. S3 cards only: flake-prone timing cuts, ranking tests that never call _score, a GIL-releasing off-loop stub, and elapsed_ms copy.
