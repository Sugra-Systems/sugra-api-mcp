## summary
The cached profile answers the same membership and phrase questions as the old per-field tokenization: each field is a frozenset of _tokens of the same text, alias phrases compare against the same joined token string _phrase_has built, and the cache keeps the Endpoint object so a reused id cannot return another object's profile. Production search runs on one worker, so the event loop and the worker do not build profiles concurrently. query_limit_error is the first work in search_endpoints, fetch_data, the CLI search command, and search_catalog; characters are counted before any regex, and 64 terms with repeats counted matches scoring cost and will not refuse a realistic agent query. Admission and release of tool calls and search slots run under locks, fetch_data delegates to call_endpoint as a function so the in-flight count does not nest, and cancellation, deadline, and worker exceptions return both counters to zero. Catalog search no longer runs on the loop; wrap_future is awaited on the loop that submitted it. One caller is capped at half of each process cap, which closes the round-2 fairness finding for this change; a source that mints many sugra_ Bearers is still many callers and needs a limit in front of the service, not inside it. Refusal spans carry only the registered tool name and an allowlisted code.
